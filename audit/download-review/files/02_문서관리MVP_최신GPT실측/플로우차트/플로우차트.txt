2. 프로세스 개요

2.1 프로세스 정보

이 문서는 회의록 문서 관리 MVP의 사용자 흐름과 내부 처리 흐름을 정리합니다. MVP의 목표 흐름은 사용자가 로그인한 뒤 회의록을 입력하고 문서를 생성하여 Word 또는 PDF로 내려받는 것입니다. 성공 기준으로 명시된 항목은 저장된 섹션의 재사용, 생성 취소 후 이전 응답의 무시, 내려받은 문서에서 표와 다이어그램이 빠지지 않는 것입니다.

범위에는 로그인, 회의록 입력, 문서 생성, Word 및 PDF 내려받기가 포함됩니다. 생성 중 화면을 나가면 작업이 멈출 수 있다는 우려에 대응하여, 완료된 섹션을 기기에 저장하고 사용자가 돌아오면 이어서 생성하는 방안이 제시되었습니다. 공유 링크와 결제는 이번 범위에서 제외됩니다. 회원가입 및 비밀번호 찾기는 회의에서 처리 방식이 정해지지 않았으므로 상세 흐름을 확정하지 않습니다.

관련 시스템으로 확인된 것은 사용자의 기기 저장 기능과 Word·PDF 문서 생성·내려받기 기능입니다. 이들이 어떤 저장소, 서버, API, 인증 체계와 연동하는지는 회의에서 정해지지 않았습니다. 아래의 시스템 연동 및 오류 대응 세부안 중 회의에 명시되지 않은 항목은 모두 제안 또는 추정 필요로 표시합니다.

3. 주요 시나리오 플로우

3.1 회원가입 플로우

회의에서 확인된 범위는 로그인 기능입니다. 회원가입의 지원 여부, 가입 화면, 이메일 검증, 비밀번호 규칙 및 계정 생성 절차는 정해지지 않았습니다. 따라서 아래 흐름은 실제 기능이 합의된 것으로 간주하지 않으며, 로그인에 필요한 계정의 생성 경로를 확정하기 위한 확인 항목으로 제시합니다.

시작 조건은 사용자가 로그인할 계정을 보유하지 않은 경우로 가정합니다. 종료 조건은 계정 생성 방식이 확정되어 계정을 사용할 수 있게 된 시점으로 둘 수 있으나, 이는 제안이며 회의 결정이 아닙니다. 회원가입을 누가 처리하고 어떤 시스템이 계정을 생성하는지도 추정 필요입니다.

이 흐름을 확정하려면 회원가입을 MVP에서 제공할지, 계정 생성이 별도 절차인지, 필수 입력값과 검증 방식이 무엇인지 확인해야 합니다. 그 전까지는 로그인 실패 시 회원가입 화면으로 유도하는 등 구체적인 동작을 확정하지 않습니다.

2. 가입 입력 항목, 이메일 인증, 비밀번호 조건, 약관 동의 및 계정 저장 방식은 모두 추정 필요입니다. 예시 흐름에 등장하는 구체적인 인증·검증 규칙은 본 문서의 확정 요건으로 사용하지 않습니다.

4. 계정 생성 실패 시의 재시도나 오류 안내 방식은 정해지지 않았습니다. 제품·개발 담당자가 가입 제공 여부와 운영 방식을 결정한 후 상세 흐름을 갱신해야 합니다.

3.2 로그인 플로우

로그인은 회의에서 MVP에 포함된 기능입니다. 시작 조건은 사용자가 로그인 화면에 진입하는 것입니다. 종료 조건은 로그인에 성공해 회의록 입력 단계로 진행하거나, 실패 안내를 받고 재시도 또는 종료를 선택하는 경우로 정의할 수 있습니다. 실패 후의 구체적인 동작은 추정 필요입니다.

주요 참여자는 로그인 정보를 입력하는 사용자와 로그인 기능을 제공하는 제품 시스템입니다. 김PM과 이개발이 회의에서 담당자로 제시되었지만, 로그인 화면·인증 처리·장애 대응 단계별 소유자는 구체적으로 배정되지 않았습니다.

로그인 완료의 확인 기준은 사용자가 회의록 입력 단계에 진입할 수 있는 상태가 되는 것입니다. 인증 방식, 입력 정보, 세션 유지 방식, 인증 오류 메시지 및 계정 잠금 정책은 정해지지 않았으므로 구현 전에 확인이 필요합니다.

2. 인증에 성공하면 회의록 입력으로 이동하는 것이 전체 업무 흐름에 부합하는 연결 방식입니다. 로그인 성공 뒤의 화면 이동은 사용자 흐름을 연결한 설계 제안이며, 세부 화면 구성은 확정되지 않았습니다.
3. 인증 실패 시 재입력을 허용할지, 계정 찾기나 가입 안내를 제공할지는 정해지지 않았습니다. 따라서 다이어그램의 재시도는 필요한 분기를 나타낸 것이며, 화면 동작과 정책은 확인이 필요합니다.
4. 네트워크 오류, 서버 오류, 응답 지연 및 세션 만료에 대한 구체적인 처리 기준은 회의에서 다루지 않았습니다. 이 항목들은 아래 예외 처리 절의 제안으로 구분합니다.

3.3 비밀번호 찾기 플로우

비밀번호 찾기 기능과 절차는 회의에서 정해지지 않았습니다. 로그인 기능이 MVP에 포함된다는 사실만으로 비밀번호 재설정 기능의 제공 여부, 재설정 수단 또는 본인 확인 방식까지 확정할 수 없습니다.

따라서 시작 조건과 종료 조건은 실제 기능이 제공되는지 결정된 이후 정의해야 합니다. 사용자가 비밀번호를 잊은 경우 로그인 화면에서 어떤 조치를 할 수 있는지, 담당 시스템이 무엇인지 모두 추정 필요입니다.

이 흐름은 개발 요건이 아니라 확인 항목을 명확히 하기 위한 것입니다. MVP에서 제공하기로 결정한다면 본인 확인 방법, 요청 제한, 오류 안내, 재설정 완료 조건을 별도로 정해야 합니다.

2. 이메일이나 문자 메시지를 통한 본인 확인, 임시 비밀번호 발급, 재설정 링크 제공 등의 방식은 모두 미정입니다. 어느 방식을 채택할지는 제품 및 보안 요구사항 확인 후 결정해야 합니다.
3. 본인 확인 실패, 재설정 요청 실패, 재설정 정보 만료 등에 대한 오류 문구와 복구 경로도 정해지지 않았습니다.
4. 비밀번호 찾기 미지원이 확정되더라도 사용자가 로그인할 수 있는 대체 경로가 필요한지 확인해야 합니다. 대체 경로의 제공 여부는 회의 근거가 없으므로 추정 필요입니다.

2. 취소 후 이전 응답을 무시하는 것은 명시된 성공 기준입니다. 따라서 취소가 발생한 작업과 이후 새로 시작된 작업의 응답을 구별하고, 취소 이전 응답이 현재 문서 결과를 덮어쓰지 않도록 검증해야 합니다. 구체적인 구현 방식은 추정 필요입니다.
3. 표와 다이어그램의 누락 없음은 내려받기 결과의 성공 기준입니다. Word와 PDF 각각에서 확인하는 구체적인 검사 방법, 누락 발견 시 사용자 안내 및 자동 복구 여부는 정해지지 않았습니다.
4. 저장 실패, 네트워크 장애, 로그인 오류 및 문서 생성 실패에 대한 빈도나 재시도 정책은 회의 근거가 없습니다. 오류 분류와 복구 방식은 임의로 확정하지 않고 제품·개발 담당자의 확인 항목으로 남깁니다.

5.1 로그인 및 문서 생성 연동

회의에서 확인된 연동 요구는 로그인 이후 회의록 입력·문서 생성이 이어지고, 완료된 섹션이 기기에 저장되며, 사용자가 돌아오면 이어서 생성하는 것입니다. 통신 프로토콜, 데이터 형식, 로그인 인증 방식, 서버 구성 및 API 경로는 정해지지 않았습니다. 따라서 아래 연동 구조는 기능 간 관계를 나타내며 실제 기술 구성을 확정하지 않습니다.

장애의 영향 범위는 구현 구조에 따라 달라집니다. 예를 들어 로그인에 실패하면 문서 작업을 시작할 수 없을 수 있고, 기기 저장에 실패하면 재방문 후 이어서 생성하는 흐름에 영향을 줄 수 있습니다. 이러한 영향은 흐름상의 가정이며, 시스템이 실제로 어떻게 동작하는지 검증이 필요합니다.

6.1 데이터 처리 플로우

데이터 수집 대상은 사용자가 입력하는 회의록 내용입니다. 입력 화면의 필수 항목, 허용 형식, 길이 제한, 누락 검사 및 중복 처리 규칙은 회의에서 정해지지 않았습니다. 따라서 입력 단계의 세부 검증 규칙은 추정 필요입니다.

회의에서 확인된 내용 처리 원칙은 원문 내용을 바꾸지 않는 것입니다. 표지, 목차, 표 스타일을 통일하되 내용 자체는 변경하지 않는다는 점이 명시되었습니다. 문서 생성 기능은 이 원칙을 지켜야 하지만, 원문 보존을 시스템에서 어떤 방식으로 검증할지는 미정입니다.

생성 중에는 완료된 섹션을 기기에 저장하고, 복귀 시 그 섹션을 재사용해 이어서 생성합니다. Word와 PDF 내려받기 결과는 표와 다이어그램의 누락 여부를 확인해야 합니다. 생성 데이터의 영구 저장, 서버 보관, 버전 관리 및 삭제 정책은 회의에서 정해지지 않았습니다.

6.3 서식 적용 및 내려받기 플로우

서식 적용 범위는 내용 자체를 바꾸지 않고 표지, 목차, 표 스타일을 통일하는 것입니다. 다이어그램은 내려받기 결과에서 누락되지 않아야 하지만, 다이어그램의 시각적 서식까지 통일하는지는 회의에서 정해지지 않았습니다.

내려받기 형식은 Word와 PDF입니다. 사용자가 어느 형식을 먼저 선택하는지, 두 형식을 한 번에 받을 수 있는지, 변환 실패 시 어떤 안내를 할지는 미정입니다. 아래 흐름은 사용자가 형식을 선택해 내려받는 절차를 제안합니다.

완료 기준은 내려받기가 끝나고 표와 다이어그램이 결과물에 누락 없이 포함되는 것입니다. Word와 PDF를 각각 검증할지, 자동 검사와 수동 확인 중 어떤 방식을 쓸지는 추정 필요입니다.

상세 설명

1. 생성된 문서에 표지, 목차, 표 스타일을 적용합니다. 이 과정에서 회의록의 실제 내용을 변경하지 않는 것이 원칙입니다.
2. 사용자는 Word 또는 PDF 형식으로 내려받습니다. 두 형식을 제공한다는 점은 회의에서 확인되었으나, 변환 방식과 화면에서의 선택 절차는 정해지지 않았습니다.
3. 내려받은 결과에서 표와 다이어그램이 빠지지 않았는지 확인해야 합니다. 이는 성공 기준에 포함된 항목이며, 형식별 검증 절차는 추가 설계가 필요합니다.
4. 결과에 요소가 누락되거나 내려받기에 실패한 경우의 수정·재시도 방법은 미정입니다. 실제 구현에서는 원인 확인, 재처리 가능 범위, 사용자 안내를 별도로 정해야 합니다.
