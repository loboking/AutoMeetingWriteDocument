테스트 판정 원칙

· P0: 핵심 기록 흐름 차단, 데이터 유실·중복, 사용자 간 데이터 노출, 개인정보의 부적절한 외부 전송 등 출시 차단 수준의 결함
· P1: 주요 기능 오동작이나 반복 사용에 큰 지장을 주는 결함
· P2: 기능 사용은 가능하나 표현·배치·세부 사용성에 영향을 주는 결함
· 테스트 케이스 상태는 작성 중, 시험 가능, 통과, 실패, 보류로 관리합니다. 상태명은 시험 관리 시 사용할 문서상 분류이며 회의에서 확정된 상태명이 아닙니다.
· 미확정 항목은 임의의 기대값으로 통과·실패를 판정하지 않습니다. 구현 확정 전까지 보류 또는 시험 전 확인 필요로 관리합니다.

3.2 테스트 도구

회의에서는 특정 시험 도구나 자동화 도구를 확정하지 않았습니다. 아래는 시험 유형에 맞춰 선정할 도구 범주이며, 제품명과 명령어는 추정 필요입니다.

단위·통합 시험

· 날짜·시간·양 환산·영양소 집계 로직의 자동 시험
· 데이터베이스 시험 자료 초기화와 사용자별 권한 검증
· 외부 음식 공급자 응답을 대체하는 시험 자료 또는 모의 응답
· 적용 언어·도구·자동 실행 절차는 추정 필요

E2E 시험

· iOS와 안드로이드의 핵심 경로를 대상으로 제한적으로 자동화
· 검색 결과 없음, 네트워크 오류, 권한 거부 등 주요 예외 상태는 수동 시험도 병행
· 자동화 도구, 실행 장치, 화면 선택 방식은 추정 필요

API 시험

· 인증·기록·리포트·알림·삭제 API 요청과 응답 확인
· 요청 재시도 시 중복 저장이 발생하지 않는지 확인
· 실제 API 경로와 인증 방식이 확정되지 않았으므로 선행 API 문서 경로를 확정 경로로 사용하지 않음
· 시험 도구와 호출 절차는 추정 필요

개인정보·네트워크 시험

· 외부 음식 API로 전송되는 자료가 검색어만인지 확인
· 제품 분석 이벤트 및 오류 진단 자료에 음식명·칼로리·체중·자유 입력 내용이 포함되지 않는지 확인
· 푸시 본문에 개인 식단 정보가 포함되지 않는지 확인
· 네트워크 요청 확인 도구와 로그 접근 권한은 추정 필요

3.3 테스트 환경

실제 환경 주소, 데이터베이스 종류, 배포 구조는 회의에서 확정되지 않았습니다. 시험 환경을 운영 자료와 분리해야 하며, 아래 환경명과 주소는 예시가 아닌 추정 필요 항목입니다.

환경·자료 관리 기준
