2. 테스트 개요

2.1 프로젝트 정보

회의록 문서 관리 MVP의 목표는 사용자가 로그인하고 회의록을 입력한 뒤 문서를 생성하여 Word와 PDF로 내려받을 수 있도록 하는 것입니다. 개발 기간은 4주로 제시되었으나, 정확한 개발 시작일과 종료일은 확인되지 않았습니다. 이에 따라 테스트 기간은 개발 일정과 기능 배포 계획을 확인한 뒤 확정해야 합니다.

생성 도중 화면을 벗어나 작업이 멈출 수 있다는 위험이 제기되었습니다. 이를 고려한 설계로 완료된 섹션을 기기에 저장하고, 사용자가 돌아오면 저장된 섹션을 재사용해 이어서 생성하는 방식이 제시되었습니다. 성공 기준으로는 저장된 섹션 재사용, 취소 후 이전 응답 무시, Word와 PDF 다운로드에서 표와 다이어그램이 누락되지 않는 것이 확인되었습니다.

문서 서식은 내용 자체를 바꾸지 않고 표지·목차·표 스타일을 통일하는 방향입니다. 공유 링크와 결제는 이번 범위에서 제외하기로 했습니다. 김PM과 이개발이 담당자로 제시되었지만, 각 테스트 활동의 담당 배정, QA 인원, 테스트 환경, 예산 및 사용자 수 목표는 정해지지 않았습니다. 해당 항목은 착수 전 확인이 필요합니다.

아래 측정 기준은 테스트 가능성을 높이기 위한 제안이며, 회의에서 합의된 제품 목표와 구분합니다.

☐ 생성 취소 후 이전 요청의 응답이 화면이나 저장 결과에 반영되지 않는지 검증한다.

☐ 제안: 배포 차단 수준의 결함 0건을 퇴수 기준으로 삼는다. 결함 등급과 허용 기준은 이해관계자 확인 필요다.
☐ 코드 커버리지, 응답 시간, 동시 사용자 수 등 수치 목표는 회의에서 정하지 않았다. 수치 목표 설정은 추정 필요다.

3. 테스트 전략

3.1 테스트 접근 방식

4주 MVP 일정에 맞춰 개발과 테스트를 병행하는 점진적 접근을 제안합니다. 다만 회의에서 개발 방법론이나 스프린트 구조를 정하지 않았으므로, 애자일 방식이나 특정 스프린트 운영을 확정 사실로 간주하지 않습니다. 개발 방식과 배포 주기는 김PM·이개발과 확인합니다.

기능이 준비되는 대로 단위·통합 검증을 진행하고, 기능 단위 배포 후 핵심 사용자 흐름을 검증합니다. 특히 기기 내 저장 및 재사용, 취소 이후 응답 처리, Word·PDF 출력은 성공 기준에 직접 연결되므로 우선순위를 높입니다. 회의에서 화면 이탈 시 생성이 멈출 수 있다는 우려가 제기된 만큼, 중단·복귀 시나리오를 일반 성공 경로와 함께 검증합니다.

자동화 도구와 자동화 비율은 회의에서 정하지 않았습니다. 따라서 자동화 비율을 임의의 확정 목표로 두지 않습니다. 제안으로는 반복 실행 가치가 높은 핵심 경로부터 자동화하고, 생성 문서의 시각적·구조적 검사는 자동 검사와 사람 검토를 병행하는 것입니다. 도구와 자동화 범위는 기술 스택 및 파일 생성 방식 확인 후 확정합니다.
